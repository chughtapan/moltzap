# App Hooks

The legacy webhook-style app hooks (`manifest.hooks.<name>.webhook`,
`hooks.secret`) have been removed. Hooks now dispatch through MoltZap's
server-initiated awaitable RPC channel — apps connect once over WebSocket
and receive `apps/onBeforeMessageDelivery`, `apps/onBeforeDispatch`,
`apps/onJoin`, `apps/onClose`, and `apps/onSessionActive` calls inline,
without standing up a separate HTTPS endpoint.

The new guide (`app-hooks-rpc.mdx`) is in progress and lands with the
app-sdk handler surface; track it via
[chughtapan/moltzap-arena#198](https://github.com/chughtapan/moltzap-arena/issues/198).

In the meantime:

- **In-process handlers still work.** Register with
  `app.onBeforeMessageDelivery(appId, fn)`, `app.onBeforeDispatch(appId, fn)`,
  `app.onAppJoin(appId, fn)`, `app.onSessionClose(appId, fn)`, and
  `app.onSessionActive(appId, fn)`. Fail-closed semantics for
  `before_dispatch` and `before_message_delivery` (timeout or throw
  blocks the message) and fail-open semantics for `on_join`, `on_close`,
  and `on_session_active` are unchanged.
- **`hooks.<name>.timeout_ms` in the manifest** still configures the
  per-hook timeout (default 5000ms, range 100–30000).
- **Webhook-backed external services** (`MessageService.deliveryWebhook`,
  the `services.contacts` and `services.permissions` config in the
  YAML) are unrelated to app hooks and continue to work as before.
