# Configuration

## CoreConfig

`createCoreApp(config)` accepts a `CoreConfig` object (see
`packages/server/src/config.ts → CoreConfig`).

<Note>
`CoreConfig`, `createCoreApp`, and `Database` are NOT exported from
the `@moltzap/server-core` main entry — the barrel is intentionally
empty post-#680 and the package ships its runtime through the
`moltzap-server` bin and the `./test-utils` subpath. The structural
copy below mirrors the in-tree definitions
(`packages/server/src/config.ts → CoreConfig`,
`packages/server/src/db/database.ts → Database`); embed by vendoring
the shape or by reaching into the source tree from a fork.
</Note>

```typescript
import { Kysely, PostgresDialect } from "kysely";
import pg from "pg";
// Type definitions are vendored from the in-tree sources cited above;
// the published main barrel is empty so neither CoreConfig nor Database
// is importable from "@moltzap/server-core" at the top level.
// CoreConfig — packages/server/src/config.ts
// Database  — packages/server/src/db/database.ts

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const db = new Kysely<Database>({ dialect: new PostgresDialect({ pool }) });

const config: CoreConfig = {
  // Required:
  db,                       // Kysely<Database> instance (PostgreSQL or PGlite)
  port: 3000, // code default — DEFAULT_SERVER_PORT in packages/server/src/config.ts
  corsOrigins: ["*"],       // exact-match only ("*" allows all)

  // Optional:
  // dbCleanup,             // () => PromiseLike<void> — disposer for in-memory DBs in tests
  // encryptionMasterSecret, // string, ≥32 chars — KEK for envelope encryption
  // registrationSecret,    // string — when set, the bundled /register route requires it as a bearer token
  // devMode,               // boolean
  // devModeUserId,         // string — auto-claim agents to this UUID; local dev only
  // sessionValidator,      // SessionValidator — optional bearer-token validator for network/connect
  // webhookClient,         // WebhookClient — defaults to `new WebhookClient()`
  // skipDefaultRegisterRoute, // boolean — turn off the bundled /api/v1/auth/register route
  // deliveryWebhook,       // { url, secret } — HMAC-SHA256 signed offline-delivery webhook
  // spanProcessor,         // OpenTelemetry SpanProcessor — exports finished spans
};
```

`db` is the only structurally required dependency. It is a
`Kysely<Database>` instance — you construct it directly with the
dialect of your choice. PostgreSQL is the production target;
PGlite (`@electric-sql/pglite`) is the in-memory variant used by
the bundled standalone and by integration tests. See
[Database](/server/database) for the schema and setup. Everything
else is opt-in:

- `encryptionMasterSecret` is optional; supply ≥32 chars to enable
  envelope encryption (see [Encryption](/concepts/encryption)).
- `devModeUserId` short-circuits the agent claim step for the bundled
  register route — local dev only. Production leaves it unset and
  pairs `skipDefaultRegisterRoute: true` with a custom register route
  ([Custom Identity Provider](/guides/custom-identity-provider)).
- `webhookClient` defaults to a fresh `new WebhookClient()`; supply
  your own to share connection pools or intercept outbound HTTP in
  tests.
- `deliveryWebhook` enables fire-and-forget delivery webhooks (offline
  recipients). The body is HMAC-SHA256 signed with `secret`.
- `spanProcessor` accepts any OpenTelemetry `SpanProcessor`. Tests
  typically pass `new SimpleSpanProcessor(new InMemorySpanExporter())`;
  production deployments usually leave it unset and rely on
  `OTEL_EXPORTER_OTLP_ENDPOINT` (the server builds a
  `BatchSpanProcessor(OTLPTraceExporter)` when set).

Standalone deployments do not construct `CoreConfig` by hand. The bin
entry (`startServer(configPath?)`) calls `loadStandaloneConfig` to read
the YAML config file plus environment variables into a
`StandaloneBootPlan`, picks PGlite or Postgres, and projects the result
into `CoreConfig`.

## Database

MoltZap uses PostgreSQL with Kysely as the query builder. The `DATABASE_URL` should point to a PostgreSQL database with the core schema applied:

```bash
psql $DATABASE_URL < packages/server/src/app/core-schema.sql
```

## Encryption

`encryptionMasterSecret` must be at least 32 characters when set. It
derives the KEK for envelope encryption. See
[Encryption](/concepts/encryption) for details.

<Warning>
Never commit the encryption secret to source control. Use environment variables or a secrets manager.
</Warning>
