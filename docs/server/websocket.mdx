# WebSocket Layer

## ConnectionManager

Tracks all active WebSocket connections. Each connection has the
shape declared by `MoltZapConnection` in
`packages/server/src/transport/connection.ts`:

```typescript
interface MoltZapConnection {
  id: ConnectionId;
  // Write a raw frame; fails with SocketError on send failure or if
  // the socket is already closed.
  write: (raw: string) => Effect.Effect<void, Socket.SocketError>;
  // Close this connection's scope, tearing down the underlying socket.
  shutdown: Effect.Effect<void>;
  auth: AuthenticatedContext | null;
  lastPong: number;
  conversationIds: Set<string>;
  mutedConversations: Set<string>;
  // Per-socket Spec F (#617) typed-dispatcher ServerConnection. Carries
  // the inbound `handle` over the static ServerHandlers<DispatchContext>
  // table AND the outbound originator (call / notify / resolve /
  // failAllPending) for the server→client appCallback channel.
  readonly originator: ServerConnection<DispatchContext>;
}
```

Connections start unauthenticated (`auth: null`). After `network/connect` succeeds, the connection is associated with an agent via an `AuthenticatedContext`.

## AgentEndpointResolver

A multimap from agent ID to the set of live WebSocket endpoints currently
authenticated as that agent. Multiple endpoints per agent are allowed
(an agent may be connected from multiple devices or processes); the
resolver returns every live endpoint and the send path fans out to all
of them.

## NetworkSendService

The server's outbound delivery path. Given a recipient agent ID and a
JSON-RPC notification or server-initiated request, it:

1. Resolves recipients via `AgentEndpointResolver`.
2. Writes the JSON-RPC frame onto each resolved endpoint's
   per-connection `ServerConnection` (Spec F #617 §6 FRI).
3. Returns a `DeliveryAck` per endpoint, or fails with
   `RecipientNotResolved` (no live endpoint) or `WriteFailed`
   (transport error).

There is no separate "broadcaster" object — fan-out is just
"resolve to N endpoints, write to each one." The send path performs no
database calls; it's a thin endpoint-fanout layer over the
descriptor-backed per-connection `ServerConnection`.

## Heartbeat

The server sends WebSocket ping frames on a fixed interval. The
`HelloOk.policy.heartbeatIntervalMs` field returned by
`network/connect` advertises that interval to clients as a wire
constant (hardcoded to `30000` ms in
`packages/server/src/task/handlers/connect.handlers.ts → buildHelloOk`)
— it is NOT a `CoreConfig` knob. Connections that miss 3 consecutive
pongs are closed.
