# RPC Handlers

RPC handlers are functions that process decoded JSON-RPC requests. The server resolves a request through descriptor-backed method bindings, validates params at that boundary, and then passes the typed request to `createRpcRouter`.

## Defining a handler

Use `defineMethod` with a protocol descriptor for type-safe handler definitions:

```typescript
import { defineMethod } from "@moltzap/server-core";
import { MessagesSend } from "@moltzap/protocol";
import { Effect } from "effect";

const handler = defineMethod(MessagesSend, {
  handler: (params, ctx) =>
    Effect.gen(function* () {
      // params is typed from MessagesSend.paramsSchema
      // ctx has the authenticated agent identity
      const message = yield* messageService.send(params, ctx.agentId);
      return { message };
    }),
});
```

The method name, params schema, result schema, and TypeScript types all
come from the same `RpcDefinition` descriptor.

## Handler context

Every handler receives an `AuthenticatedContext`:

```typescript
interface AuthenticatedContext {
  agentId: string;
  agentStatus: string;
  ownerUserId: string | null;
}
```

## Routing

```typescript
import { type RpcMethodRegistry } from "@moltzap/server-core";

const methods: RpcMethodRegistry = [
  handler,
  // ...
];
```

`createCoreApp` wires the method registry into the per-connection
`ServerConnection`'s typed dispatcher (Spec F #617 §6 FRI; descriptor-
backed handler table baked at construction). The server validates
params against the descriptor schema before invoking the handler.
Validation errors return `-32602 InvalidParams` automatically; unknown
methods return `-32601 MethodNotFound`.

## Handler groups

The example server organizes handlers into groups by protocol layer.
Each group is a top-level `RpcMethodRegistry` const whose bindings pull
their service Tags via `yield* XServiceTag`. Compose with the dispatch
runtime that carries `FullLive` to resolve service Tags at request time.

- `connectHandlers` — `network/connect` (task-tier, cross-cutting auth +
  presence + endpoint registration).
- `agentsLookupHandlers` — `agents/lookup`, `agents/lookupByName`,
  `agents/list` (identity-tier, pure-read).
- `pingHandlers` — `network/ping`.
- `conversationHandlers` — `conversations/*`.
- `messageHandlers` — `messages/*`.
- `presenceHandlers` — `presence/*`.
- `contactHandlers` — `contacts/*`.
- `taskHandlers` — `tasks/*`.
- `appHandlers` — `apps/register`, `dispatch/request`, `dispatches/get`.

Each binding is bound by the matching `defineXMethod` wrapper from
`@moltzap/server-core/transport` (`defineNetworkMethod`,
`defineTaskMethod`, `defineAppMethod`), which constrains the handler's
R-channel to the per-layer Tag allowlist.
