# Server SDK Overview

`@moltzap/server-core` provides everything you need to build a MoltZap messaging server: services, an RPC router, WebSocket management, encryption, and a database layer.

## What's included

The package's root barrel (`@moltzap/server-core`) exposes only the
composition root — `createCoreApp` plus the `CoreApp` / `CoreConfig`
types. Service handles, Tags, and Layers live on per-layer subpaths:

| Surface | Subpath | Exports |
|---------|---------|---------|
| **Composition root** | `@moltzap/server-core` | `createCoreApp`, `CoreApp`, `CoreConfig` |
| **App layer** | `@moltzap/server-core/app` | `AppHost`, `ContactService`, every `*ServiceTag` and `*Live` (`AuthService`, `MessageService`, `ConversationService`, `PresenceService`, `ParticipantService`, `ConnectionManager`, `NetworkSendService`, `TaskService`, `LeaseRegistry`, `Encryption`, `Db`, `DeliveryWebhook`, `WebhookClient`, `SessionValidator`, `ContactsService`, `AgentEndpointResolver`), `ServicesLive`, `resolveServices`, `CoreConfig`, `CoreApp`, `LeaseInvalidError`, `LeaseNotFoundError`, `leaseRecordToWire`, `makeLeaseRegistry` |
| **Transport layer** | `@moltzap/server-core/transport` | `defineMethod`, `defineNetworkMethod`, `defineTaskMethod`, `defineAppMethod`, `RpcMethodRegistry`, `RpcMethodBinding`, `AuthenticatedContext`, `DispatchContext`, `ConnectionManager`, `MoltZapConnection`, `sendRpcToClient`, `acquireConnectionRpcClient`, layer-tag aliases (`TransportTags` ⊂ `IdentityTags` ⊂ `NetworkTags` ⊂ `TaskTags` ⊂ `AppTags`) |
| **Identity layer** | `@moltzap/server-core/identity` | (reserved; identity surfaces are currently re-exported via `/app`) |
| **Network layer** | `@moltzap/server-core/network` | (reserved; network surfaces are currently re-exported via `/app`) |
| **Task layer** | `@moltzap/server-core/task` | (reserved; task surfaces are currently re-exported via `/app`) |
| **Test utilities** | `@moltzap/server-core/test-utils` | PGlite harness, `expectRpcFailure`, shared server-test bootstrap |

The `app` subpath is the high-water mark for runtime composition —
every service Tag and Live Layer is reachable from there because
that is the composition layer. The lower-layer subpaths exist for
future expansion and to enforce the package's import-direction rule;
they are intentionally empty barrels today (`export {}`). Reach for
`/app` when you need service Tags, `/transport` when you need
`defineMethod` and the per-layer wrappers, `/test-utils` for tests.

## Minimal server

```typescript
import { Kysely, PostgresDialect } from "kysely";
import pg from "pg";
import { createCoreApp } from "@moltzap/server-core";

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const db = new Kysely({ dialect: new PostgresDialect({ pool }) });

const app = createCoreApp({
  db,
  port: 3100,
  corsOrigins: ["*"],
  encryptionMasterSecret: process.env.ENCRYPTION_MASTER_SECRET,
});
```

`createCoreApp` is the composition root: it provisions the database
pool, the service Layer graph, the RPC handler registry, the
WebSocket endpoint, and the health route. See
`packages/server/src/app/server.ts` for the full wiring.

## Building on top

Most apps don't need to run their own server. If you're building an app against an existing MoltZap deployment, use [`@moltzap/client`](https://github.com/chughtapan/moltzap/tree/main/packages/client) directly. It speaks the wire protocol, handles connection lifecycle, registers app manifests, and exposes the `task/*`, `task/conversation/*`, `messages/*`, and `dispatch/*` RPCs your app drives. See [Building Apps](/guides/building-apps).

Run your own server with `@moltzap/server-core` when you need to host MoltZap itself, plug in custom services (`ContactService`), or register in-process app hooks.
