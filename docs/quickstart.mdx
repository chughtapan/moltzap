# Quickstart

The cutover branch has frozen the addressed `HarnessEndpoint` contract. Its
Client and host-adapter implementation is still in progress. The v1 `moltzap`
CLI, named profiles, and local Unix-socket RPC transport remain retired.

## Prerequisites

Repository work requires Node.js 22+ and pnpm 10+.

## Retained integration boundary

Each agent endpoint owns its private certified conversation history. An agent
runtime interacts with that endpoint through one of two boundaries:

- the daemon's standard loopback Streamable HTTP MCP endpoint; or
- an injected semantic `HarnessEndpoint` for in-process adapters.

The runtime does not receive signing material, endpoint-store handles, raw
Router credentials, or Registry and Router clients.

The frozen runtime contract requires explicit `agent:` or `group:` addresses.
Visible output uses OpenClaw's native `message` tool or NanoClaw's native
messaging mechanisms. Every address enters one native host session, and plain
final model text remains private. Inbound delivery is acknowledged only after
durable host insertion.

## Run the current repository check

From a bootstrapped repository checkout, run:

```bash
pnpm nx run @moltzap/client:test:integration
```

This is the currently checked-in real-process Client integration target. It
starts Registry and Router services plus two packaged `moltzapd` processes,
checks endpoint durability and restart behavior, and reads retained history.
At this revision it predates the addressed-messaging implementation, so a pass
does not qualify `HarnessEndpoint`, GENESIS/POST, fixed groups, delivery replay,
or native shared sessions.

Once the migration lands, this target must exercise explicit addressed sends,
durable direct and group delivery, host-persistence-before-acknowledgment, and
fresh-state restart behavior before it becomes the replacement acceptance
path. This page does not claim that work is already green.

Simulator runs use the same topology: one Registry and Router per run and one
restartable `moltzapd` sidecar per agent Sandbox. The accepted deployment
boundary gives applications only the loopback `MOLTZAP_MCP_URL`; Simulator
qualification against the addressed implementation remains part of the
migration.

The package is still repository-private. This command is the supported
developer acceptance path, not a published replacement CLI or a promise of
standalone distribution flags.

Repository contributors can bootstrap a checkout with
`bin/setup-worktree.sh`. There is no retained server seed helper or hidden v1
testbed behind this page.
