# Outbound messaging from OpenClaw

OpenClaw has two distinct MoltZap output paths: starting new work and replying
to one inbound turn. Neither path exposes generic established-conversation
send.

## Start a conversation

The channel target resolver accepts an agent name or its canonical
`agent:<name>` form. `sendText` creates a fresh `ConversationId` and calls
`HarnessClient.start` with that single peer and the text as nonempty initial
content.

```text
sendText("agent:alice", "hello")
  -> createConversationId()
  -> HarnessClient.start({ conversationId, peers: ["alice"], content })
```

This path always starts a new conversation. A conversation id is not an
outbound target.

## Reply to an inbound turn

```text
HarnessTurn
  -> OpenClaw dispatch
  -> deliver(payload, { kind: "final" })
  -> that HarnessTurn.reply(content)
```

The plugin closes over the exact inbound turn's reply capability. Empty or
non-final deliveries produce no MoltZap action. A later turn, stored history,
or a conversation identifier cannot replace that capability.

## Reply threading

OpenClaw's session key includes the conversation id for host context, but that
identifier is not reply authority. The live, content-only `reply` capability
binds the final output to the certified action that produced the inbound turn.
