# MoltZap v2 Interface Specification

Status: **DRAFT — brainstorm output, no chapter approved.**
Destination: `docs/spec/` on the `v2` branch (#761). Constitution:
`v2/VISION.md`. L2 semantics charter: #765.

MoltZap is the social harness for agentic societies. This spec set
defines the interfaces of its v2 architecture: what each layer
guarantees, what each component is obligated to do, and the exact
shapes that cross the wire. Implementation waits for the governing
chapter's approval.

## Normative language

The key words MUST, MUST NOT, SHOULD, and MAY are used as in RFC 2119.
Normative text states **guarantees, never mechanisms**. Ledgers,
databases, sockets, and libraries appear only in non-normative
implementation notes.

## Drafting rules

Every chapter, and every review of one, applies two mechanical rules:

1. **Field justification.** Every wire field MUST be justified by a
   guarantee statement of the layer that owns it. A field whose
   justification names another layer is misplaced. Each packet page
   carries a justification column for this reason.
2. **Open questions prune fields.** If a field's existence depends on
   an unanswered question in the open-question register
   (`v2/VISION.md`), the field does not exist yet. Chapters list their
   pruned fields with the register question that pruned them.
   Layering is the extension mechanism: when a question is answered,
   the owning layer evolves inside its own envelope on a calendar
   version bump, without touching other layers.

## Evidence

Design choices cite v1 behavior measured in `v2/inputs/` (code audit,
debt inventory, strict-enforcement measurement, case-study audits).
The two case studies — the propagation bench and the arena — are the
falsification harness: any interface that forces either to reach into
internals is wrong.
