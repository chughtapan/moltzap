AREA: agent-to-agent communication protocols

SUMMARY: The field has consolidated around a two-layer default: MCP for agent-to-tool (de facto standard, ~97M monthly SDK downloads, 18k+ indexed servers) and A2A for agent-to-agent, with A2A v1.0 shipping in early 2026 under Linux Foundation governance (150+ member orgs, 22k GitHub stars, SDKs in 5 languages, shipped in Azure AI Foundry, Copilot Studio, and Amazon Bedrock AgentCore Runtime). A2A's core shape is task-delegation: an AgentCard for discovery, a Task with an explicit 8-state FSM, Messages and Artifacts composed of one-of Parts, delivered via polling, streaming, or webhooks over three functionally-equivalent bindings (JSON-RPC 2.0, gRPC, REST). AGNTCY (Cisco Outshift, now Linux Foundation) occupies the layers A2A leaves open — protocol-agnostic agent description (OASF), a DHT-routed content-addressed directory, DID-based identity, and a secure messaging substrate (SLIM) — but its adoption evidence is thin relative to its documentation surface. Convergence under the Linux Foundation's AAIF is institutional rather than technical; the sharpest criticisms are that adoption claims are mostly logo collections rather than named production case studies, and that all current protocols treat agents as task workers, leaving negotiation, shared context, governance, fine-grained authorization, and observability as unstandardized application-layer problems.

INTERFACE_PATTERNS:
  - Self-describing signed agent manifest (A2A AgentCard, OASF record): identity + capability flags + skills + security schemes + endpoint/binding declarations + extension URIs, fetched before any interaction and gating which operations are legal
  - Task as a stateful server-side resource with an enumerated FSM whose states are partitioned into active / interrupted (INPUT_REQUIRED, AUTH_REQUIRED) / terminal — the interrupted class is the protocol's only concession to conversation
  - Uniform content container: Message and Artifact both compose arrays of one-of Parts (text | bytes | url | structured data) tagged with mediaType, so the same content model serves conversation and deliverables
  - Three-tier result delivery offered simultaneously: poll (GetTask), subscribe/stream (typed update events: TaskStatusUpdateEvent, TaskArtifactUpdateEvent), and webhook push with server-stored CRUD-managed notification configs
  - Multi-binding with mandated functional equivalence: one abstract operation set projected onto JSON-RPC 2.0, gRPC, and REST, with version and extension negotiation carried in transport-appropriate service parameters (A2A-Version, A2A-Extensions headers/metadata)
  - URI-identified opt-in extensions declared in the manifest and echoed per-message, with a typed error (ExtensionSupportRequiredError) when a required extension is unsupported
  - Discovery decoupled from wire protocol: a separate description schema (OASF) plus a registry/directory layer (content-addressed records, skill-taxonomy-routed DHT) that can describe agents speaking any protocol
  - contextId as a lightweight grouping key spanning multiple tasks — shared context by correlation ID rather than by any semantic common-ground mechanism
  - Capability-gated operations with explicit typed refusals (PushNotificationNotSupportedError, UnsupportedOperationError) instead of silent degradation
  - Layered composition as the ecosystem default: MCP vertically (agent-to-tool), A2A horizontally (agent-to-agent), identity/trust as a cross-cutting third layer (OAuth 2.1 today, DIDs/verifiable credentials aspirationally)

PITFALLS:
  - Logo adoption is not production adoption: A2A's own foundation press release claims 150+ organizations and 'production deployments across industries' while naming zero customer case studies; the only hard numbers are stars, member counts, and vendor platform integrations
  - Task-worker framing forecloses conversation: all shipping protocols model unilateral delegation (send message -> task -> artifacts); negotiation, clarification loops, joint problem-solving, speech-act intent, and common-ground establishment have no protocol-level home (the academic critique explicitly maps this back to what FIPA-ACL had and these dropped)
  - Extension mechanisms do not substitute for first-party primitives: A2A's extension system theoretically supports governance semantics, yet six months in, zero governance extensions had been proposed — semantics nobody standardizes never appear (the governance-gaps paper finds voting, membership, dissent preservation, and human escalation absent from every protocol)
  - Coarse task-state visibility: an 8-state FSM tells you WORKING but nothing about progress inside a long-running task; observability (OTel spans, structured invocation logs, tamper-evident audit) is universally punted to implementers
  - Discovery remains manual in practice despite AgentCards and directories; the 'agent marketplace' vision quietly assumes identity, reputation, billing, compliance, sandboxing, liability, and dispute resolution that no protocol supplies
  - Security declared out of scope: A2A is not a security architecture — fine-grained authorization, admission control, and cross-org trust are left to surrounding infrastructure, which mostly does not exist yet
  - Architecturally ambitious designs stall on missing infrastructure: ANP's DID-based identity is the most principled design and has zero production deployments because resolver/tooling ecosystems lag HTTP by years
  - Protocol-status churn and conflicting narratives (is ACP merged into A2A or a parallel track? sources disagree in 2026) — convergence under the Linux Foundation AAIF is governance alignment, not technical unification, so betting on 'the merged standard' is premature
  - Operational overhead for the common case: practitioners note most projects do not need an inter-agent protocol at all, and adopting one adds concepts, failure modes, debugging surface, and security obligations that in-process orchestration avoids
  - Simpler-than-A2A alternatives pay elsewhere: ACP's plain-REST model loses streaming for long-running work and expressive lifecycle management, and its centralized registry is a bottleneck — simplicity at the wire level pushed complexity to operations

IMPLICATIONS:
  - Copy A2A's data-model bones — they are becoming lingua franca: one-of Part content containers shared by messages and artifacts, an explicit task FSM with an interrupted-state class (INPUT_REQUIRED / AUTH_REQUIRED), capability flags with typed refusal errors, and URI-negotiated extensions. Interop with AgentCard/Task shapes is table stakes for adoption.
  - Copy the delivery triad (poll / typed-event stream / webhook push with server-stored configs) and multi-binding-with-functional-equivalence discipline; both are proven and expected by tooling.
  - Copy AGNTCY's separation of concerns even if not its implementation: description schema (protocol-agnostic records with a skill taxonomy) and discovery/registry are distinct layers from the wire protocol, which lets one stack describe heterogeneous agents. Content-addressed, taxonomy-routed records are a sound design worth stealing.
  - Avoid making task delegation the only communicative shape: a layered stack should reserve an explicit layer for conversational semantics — performative/intent tagging, negotiation, clarification, common-ground state — above transport and below application, because this is the loudest documented gap and a correlation ID (contextId) is not shared context.
  - Avoid relying on an extension mechanism for load-bearing semantics: anything the stack considers essential (human escalation, audit/replay, admission control, progress reporting inside long-running tasks) must be a first-party primitive, or the A2A experience says it will simply never be standardized by the ecosystem.
  - Build observability in natively (per-message/task trace spans, structured tamper-evident logs): every 2026 protocol comparison lists this as an unresolved implementer burden, so it is a differentiator with no incumbent.
  - Treat identity/trust as a first-class stack layer but with a pragmatic dual track: OAuth 2.1-style schemes for deployability today, DID/verifiable-credential hooks for later — ANP shows that leading with decentralized identity alone strands you at reference-implementation stage.
  - Design for honest incremental adoption: the credible growth path in this space is a vendor-shipped runtime integration (Azure/Bedrock pattern), not a member-organization list; make the stack valuable for a two-agent deployment before a 150-org federation.
  - Expect institutional convergence, not technical: align governance-wise with the Linux Foundation AAIF orbit and the prospective MCP-to-A2A bridging work (tool invocation triggering agent delegation), since cross-layer bridging is where the standardization energy is going in late 2026.

AREA: Group communication and collective operations (communicators, atomic broadcast, virtual synchrony, LLM group-chat turn-taking)

SUMMARY: The classic lineage converged on a stable interface shape: an opaque communicator/channel handle bound to a ranked membership set, with collectives or multicasts scoped to that handle and membership changes delivered in-band as ordered "view" events (MPI_Comm, ncclComm_t, JGroups JChannel/View, Corosync CPG, Derecho Group/View). In production, symmetric total-order-multicast toolkits (Isis/Spread lineage) have largely been displaced by consensus-backed replicated logs consumed by deterministic state machines — ZAB under ZooKeeper, Raft under etcd and Aeron Cluster — where "total order" is an append-to-log plus ordered-callback API rather than a multicast primitive. Survivors each own a niche: MPI/NCCL for HPC and GPU-training collectives, JGroups inside JBoss/Infinispan clustering, Corosync CPG under Pacemaker HA, Aeron Cluster in trading systems; Derecho (Cornell, RDMA-based, active through v2.4.2 Jan 2026) shows the virtual-synchrony model still being modernized but remains research-grade. On the LLM side, group coordination is re-emerging as centralized chat managers (AutoGen SelectorGroupChat, AG2 GroupChat) whose turn-taking is a pluggable speaker-selection policy — round_robin/random/auto enum plus selector_func and allowed_speaker_transitions graph — which is effectively a sequencer handing out total order for free; recent research (MMAgents, Frontiers in AI 2025) shows conversation-analysis-based turn allocation (addressee designation + scored self-selection) signific

INTERFACE_PATTERNS:
  - Communicator-as-capability: an opaque handle (MPI_Comm, ncclComm_t, JChannel, cpg handle, derecho::Group) binds a membership set + rank assignment + isolated context ID; all group operations are scoped to the handle, and context isolation guarantees traffic on different communicators cannot interfere.
  - Membership as in-band versioned views: membership changes arrive as ordered events through the same delivery path as messages (JGroups viewAccepted(View), Corosync cpg_confchg_fn registered beside cpg_deliver_fn, Derecho view upcalls) — the virtual-synchrony core, letting all members agree which messages belong to which membership epoch.
  - Delivery-guarantee ladder as a small named enum, selectable per message or per group (Spread's UNRELIABLE < RELIABLE < FIFO < CAUSAL < AGREED < SAFE service types) or per stack (JGroups XML protocol composition) — the invocation API stays constant while the guarantee varies.
  - Symmetric collective verbs: every rank calls the identical function with the identical signature (MPI_ALLREDUCE, ncclAllReduce); asymmetric operations differ only by a root parameter; subgroups are forked cheaply by split(color, key) rather than enumerating members.
  - Total order as replicated log + deterministic state machine, not multicast: append via offer(), consume via an ordered callback carrying an authoritative cluster-supplied timestamp, restore via snapshot hooks (Aeron ClusteredService.onSessionMessage/onTakeSnapshot; ZAB/Raft services expose the same shape as KV+watch or partition append/consume).
  - Turn-taking as pluggable policy on a centralized manager: an enum of built-ins (round_robin, random, manual, LLM-'auto') plus function escape hatches (selector_func, candidate_func) plus a declarative transition graph (allowed_or_disallowed_speaker_transitions), with composable termination-condition objects (AutoGen/AG2).
  - Broadcast-to-all shared transcript as the default LLM context model: the group-chat manager appends every utterance to one shared history and serializes turns — a centralized sequencer that delivers total order as a side effect.
  - Addressee-designation in the message schema drives turn allocation: conversation-analysis adjacency pairs (CSSN) plus scored self-selection outperform both round-robin and pure LLM choice (MMAgents), suggesting reply-obligation should be a message field, not a manager inference.

PITFALLS:
  - Guarantees defined by config-file composition rot: JGroups' correctness depends on the ordering and choice of XML stack elements; a misconfigured stack silently changes delivery semantics with no type-level signal.
  - MPI's static-world assumption: communicator creation is a blocking collective over the parent, membership is fixed at init (NCCL inherits this), and fault tolerance was bolted on decades later — a poor fit for any domain with churn, which agent groups have.
  - Strongest-guarantee-only APIs get bypassed: SAFE/AGREED delivery costs latency, so systems that don't expose the cheaper rungs of the ladder push users to side channels; conversely Spread-style ladders survive as vocabulary even after the toolkit died.
  - The symmetric total-order-multicast toolkits (Isis, Spread, Ensemble lineage) lost to consensus-backed logs largely on operational simplicity, not theory — building a new symmetric multicast layer repeats a market-tested mistake.
  - Determinism-by-documentation: Aeron Cluster requires app code to avoid wall-clock, randomness, and hash iteration order, but nothing in the API enforces it; violations produce silently divergent replicas. Injecting time/randomness through the API is the fix, not docs.
  - Membership on a side channel breaks epochs: any design where view changes and messages travel different paths loses the agreement on which messages precede a membership change — the exact failure virtual synchrony was invented to prevent.
  - LLM-based speaker selection is nondeterministic, costs a model call per turn on the critical path, and needs heuristic patches (AutoGen's no-repeat-speaker default); LLM-coordination evaluations report agents handle sequential turn-taking but deadlock >95% under simultaneous-decision conditions.
  - Provider quirks leak into coordination APIs: AG2's role_for_select_speaker_messages parameter exists only because some LLM providers reject a trailing 'system' role — coupling group-coordination surface to model-vendor message formats.
  - Round-robin is a weak baseline that ships as the default: MMAgents' human evals scored round-robin 5.89 vs 7.45 for conversation-analysis-based allocation; frameworks defaulting to rotation leave measured quality on the table.
  - Operational coupling to privileged daemons (Corosync requires the corosync IPC user; Spread requires a daemon per host) raises the adoption floor — library-embeddable layers (JGroups, NCCL) spread further.

IMPLICATIONS:
  - Copy the communicator: make the group a first-class handle carrying membership view + rank/identity + an isolated context, with all sends/collectives scoped to it, and support cheap subgroup forking (split-by-color/key style) that doesn't require global coordination.
  - Copy in-band views: deliver membership changes as ordered events in the same stream as messages so every agent agrees which messages fall in which membership epoch — this is the single most load-bearing idea from virtual synchrony and the one LLM frameworks currently lack entirely.
  - Offer a small named guarantee ladder (best-effort / FIFO / causal / total) selectable per message or per group, expressed in the typed API surface rather than in config-file stack composition.
  - Implement the total-order rung as an append-to-log + ordered-delivery-callback + snapshot-hook service (the Aeron/ZAB/Raft shape), with authoritative timestamps supplied in the delivery callback; do not build symmetric total-order multicast.
  - If deterministic replay is a goal, enforce determinism through the API (injected time, seeded randomness, ordered iteration helpers) instead of documenting it — Aeron shows the docs-only approach leaves silent replica divergence on the table.
  - Layer turn-taking ABOVE ordered delivery as a pluggable policy: ship the proven ergonomic surface (enum of round_robin/random/manual/LLM-auto, selector_func + candidate_func escape hatches, declarative speaker-transition graph, composable termination conditions) that AutoGen/AG2 users already know.
  - Put addressee/reply-obligation fields in the message schema so CSSN-style turn allocation (adjacency-pair designation + scored self-selection) is implementable without a moderator model call per turn — the evidence says it beats both round-robin and LLM-moderator selection.
  - Keep LLM calls off the coordination critical path by default: LLM speaker selection should be one optional policy with deterministic fallbacks, given its per-turn cost, nondeterminism, and demonstrated deadlock behavior under simultaneous decisions.
  - Design for churn from day one: joins/leaves must be first-class, non-collective operations (avoid MPI's blocking-collective communicator creation), because agent groups are dynamic in a way HPC ranks are not.
  - Prefer library-embeddable over privileged-daemon architecture, and keep provider/model-format quirks quarantined in an adapter layer so they never surface as parameters on the group-coordination API (the AG2 role_for_select_speaker_messages anti-pattern).
  - The open gap this stack can own: no existing system combines epoch-consistent group membership and a guarantee ladder (distributed-systems lineage) with pluggable turn-taking policies and shared-transcript context (LLM lineage) — the two literatures have not yet been joined at the interface level.

AREA: Formally specified communication protocols as executable artifacts (multiparty session types, choreographic programming, commitment/information protocols, runtime protocol monitoring)

SUMMARY: This space has three live traditions. (1) Multiparty session types (MPST): a global protocol written in a Scribble-style DSL is mechanically projected to per-role local types, which are compiled to typestate APIs or communicating FSMs; tooling (Scribble-Java, nuscr) exists and works but is research-grade, low-star, and mostly dormant, with the one notable production deployment being Scribble-based per-endpoint monitors in the Ocean Observatories Initiative cyberinfrastructure. (2) Choreographic programming moves the whole distributed program (not just its types) into one artifact and derives each role's code by endpoint projection; the field has shifted from standalone languages (Choral) to host-language libraries (HasChor in Haskell, ChoRus in Rust, Chorex/Klor/Choret), all active but with essentially zero production adoption. (3) The commitment/information-protocol school (Singh, Chopra, Christie) rejects message-order specifications entirely: BSPL protocols declare only information causality via in/out/key parameter adornments, verified by the Tango CLI (`bspl verify safety|liveness` with concrete counterexample traces), and enacted by adapter middleware (Kiko, Mandrake) that computes "enabled forms" over unreliable UDP — a July 2025 toolsuite paper consolidates this as the most agent-relevant design. Runtime verification (Discourje, SPY) shows that dynamic per-endpoint monitoring with drop-in channel instrumentation is the practical enforcement point, since static session

INTERFACE_PATTERNS:
  - Global-artifact -> projection -> per-role view is the universal pivot: every MPST/choreography system has one canonical global description (protocol or program) and a mechanical endpoint-projection operation producing each participant's local type, monitor FSM, or code.
  - Two enforcement points recur: static (generated typestate APIs where each protocol state is a class/type whose send/receive returns the next state — Scribble-Java, nuscr, Choral) and dynamic (an automaton monitor consulted on every channel action — Discourje, SPY). Dynamic won in practice.
  - Library embedding beats standalone languages for adoption: the choreography field migrated from compilers (Chor, Choral) to host-language DSLs (HasChor monad, ChoRus traits, Discourje macros) precisely to inherit the host's editor, package manager, and libraries.
  - Declarative information-causality instead of ordering: BSPL messages carry in/out/nil parameter adornments plus `key` correlation parameters; a send is legal iff its information dependencies are satisfied by the sender's local state — ordering, retransmission, and duplication become non-issues by construction.
  - Enablement-based agent API: middleware computes the set of 'enabled forms' (legal partial messages given local state + protocol) and agent logic merely selects and completes them — a clean protocol-compliance / decision-making split (Kiko), directly analogous to presenting an LLM agent with its legal moves.
  - Verifier as a fast CLI with concrete counterexamples: `bspl verify safety|liveness` returns sub-millisecond verdicts plus an explicit violating trace and the offending parameter; canonical-enactment reduction tames exponential path explosion.
  - Drop-in channel instrumentation for monitoring: keep the implementation unchanged except swapping the channel library import and tagging channels with a spec (Discourje) — minimal-diff adoption is the explicit design goal.
  - Meaning layered above legality: commitments C(debtor, creditor, antecedent, consequent) give messages social semantics on top of the protocol's causality rules, and can be compiled to SQL queries over a message store (Cupid) so accountability state is queryable.

PITFALLS:
  - Near-total adoption failure despite 20+ years of work: Scribble-Java (~60 stars, dormant), nuscr ('not ready for production'), Choral (prototype), HasChor/ChoRus (research artifacts). The only production deployment found is the OOI monitoring integration circa 2013. Announcement-to-usage ratio is extreme; do not mistake paper volume for ecosystem.
  - Message-order-based specifications are brittle for autonomous agents: the commitment/information-protocol school's core critique is that FSM/session-type orderings over-constrain (e.g., 'Payment and Shipment in either order' is inexpressible as a well-formed protocol in classical approaches) and break under reordering, loss, and retransmission.
  - Projection well-formedness restrictions bite hard: many natural global protocols are unprojectable (choices must be located at one role and knowledge-of-choice propagated), forcing contorted specs; choreographic libraries pay this as hidden broadcasts (HasChor's `cond` broadcasts every choice to all locations).
  - Static session typing does not fit mainstream languages: linearity cannot be expressed in Java/TypeScript/Go type systems, so toolchains fall back to runtime-checked linear usage or awkward generated callback/typestate APIs; ergonomics repeatedly sank adoption.
  - Monitors historically check safety only: an exception at the violating send tells you a protocol died, not how to recover; liveness monitoring arrived only recently (Discourje 'Live at Last', 2024) and recovery/compensation remains unsolved in all of these systems.
  - Assuming reliable ordered transport bakes in fragility: TCP cannot help when a counterparty simply never sends — Mandrake's end-to-end argument is that fault handling (reminders, retries, deadlines) must live at the application/protocol layer as explicit policies.
  - Tooling fragmentation: every research group maintains an incompatible Scribble dialect or choreography embedding; there is no interchange format, no shared conformance suite, and artifacts rot when the one PhD student graduates.
  - The FIPA ACL / AUML precedent: standardized speech-act message sets with mentalist (belief/intention) semantics and informal UML orderings provided no formal model, no verification, and no compliance checking — the cautionary tale every later system cites.

IMPLICATIONS:
  - Copy the layering from the BSPL toolsuite: (1) a small declarative protocol artifact, (2) a fast verifier CLI that returns concrete counterexample traces, (3) adapter middleware that computes what is currently legal, (4) agent decision logic that only selects among enabled actions. This is the most agent-shaped architecture in the literature and maps directly onto LLM agents choosing from presented legal moves.
  - Prefer information-causality (in/out/key parameter adornments, correlation keys) over message-ordering as the primary spec semantics for a multi-agent stack: it tolerates asynchrony, loss, duplication, and reordering by construction, and preserves agent autonomy — reserve ordering constraints for where they are genuinely load-bearing.
  - Keep global-spec -> per-role projection as a first-class, early-failing operation with good diagnostics; every successful system in this space is organized around it, and unprojectable specs should be rejected at authoring time, not discovered at runtime.
  - Enforce dynamically at the channel/transport boundary (Discourje-style drop-in instrumentation, SPY-style independent per-endpoint monitors) rather than betting on static session typing in host languages — per-endpoint local monitoring composes to global safety and matches heterogeneous agent runtimes.
  - Avoid shipping a standalone language + compiler; embed the spec DSL in the host ecosystem or keep it a small textual artifact with generated adapters. The choreography field's migration from Choral-style compilers to HasChor/ChoRus-style libraries is the adoption lesson.
  - Design liveness, deadlines, and recovery in from day one: adopt Mandrake-style declarative retry/reminder policies (`when: <cron>, max tries: N`) and expect lossy transports; a monitor that only throws on safety violations is not an operations story.
  - Add a commitment layer for meaning and accountability above protocol legality: track C(debtor, creditor, antecedent, consequent) states derived from observed messages and make them queryable (Cupid compiles commitments to SQL over a message store) — this gives agents and humans a shared, auditable answer to 'who owes what now'.
  - Steal the verifier DX bar from Tango: sub-second `verify safety|liveness` with a printed violating trace and offending parameter; and steal canonical-enactment reduction to keep verification tractable as protocols grow.
  - Do not take a dependency on any existing toolchain — none is production-grade — but mine Scribble/nuscr for projection algorithms, Discourje for instrumentation ergonomics, and the BSPL suite for the agent-facing API shape.

AREA: LLM input/output screening and agent firewalls

SUMMARY: The field has three deployed layers: (1) app-embedded rail/validator middleware (NeMo Guardrails, Guardrails AI, OpenAI Agents SDK guardrails, LangChain AgentMiddleware) that hooks before/after model calls and blocks, rewrites, or raises on violation; (2) guard-model classifier services (Llama Guard 3/4, AWS Bedrock ApplyGuardrail, Meta LlamaFirewall) that return structured verdicts against a hazard taxonomy, increasingly decoupled from model invocation as standalone APIs; and (3) an emerging "agent firewall" category of network/protocol proxies (Claw Patrol, Invariant, agentgateway, Pipelock-class tools) that interpose on wire traffic — OpenAI-compatible endpoints, MCP JSON-RPC, SQL, HTTP — and enforce declarative policies with allow/deny/ask verdicts. Screening of INTER-agent messages specifically is the least mature slice: only Invariant's trace-matching policy language, LlamaFirewall's per-role scanner registration and chain-of-thought AlignmentCheck, and agentgateway's per-MCP-method processor phases address agent-internal or agent-to-tool hops, and none carries trust/provenance metadata across hops. Consensus from 2026 security literature is that classifier-based detection is probabilistic and must sit inside a defense-in-depth stack whose authoritative enforcement lives at a boundary the agent cannot route around.

INTERFACE_PATTERNS:
  - Transparent proxy interposition at an existing protocol boundary so agents need zero code changes: OPENAI_BASE_URL swap, MCP JSON-RPC middleman, wire-level SQL/HTTP/k8s parsing (Claw Patrol), mitmproxy — versus in-process library hooks.
  - Declarative policy artifacts separate from app code, but every system invents its own DSL: YAML rails config + Colang (NeMo), HCL + CEL (Claw Patrol), Python-ish trace-matching rules (Invariant), RAIL/Pydantic schemas (Guardrails AI), k8s CRDs (agentgateway), JSON DAG configs (research firewall).
  - A small closed action vocabulary recurs everywhere: allow / block (exception or canned message) / mask-redact-anonymize / rewrite-fix / ask (human-or-LLM-judge approval) / flag-for-audit — e.g. Bedrock's BLOCKED|ANONYMIZED, LangChain PII's redact|mask|hash|block, Claw Patrol's allow|deny|ask, Guardrails AI's OnFailAction enum.
  - Guard-as-a-service decoupled from model invocation: a standalone assessment call returning a structured verdict envelope — Bedrock ApplyGuardrail's {action, outputs, assessments-per-policy, confidence, latency/units}, agentgateway's gRPC CheckRequest/CheckResponse ext-processor, Guardrails AI's OpenAI-compatible server.
  - LLM-based guard classifiers with prompt-customizable taxonomies and category-coded outputs: 'safe'/'unsafe' + S-codes, first-token probability as score (Llama Guard lineage); MLCommons S1–S13 emerging as the shared hazard vocabulary.
  - Role- and hop-scoped scanner registration: LlamaFirewall's {Role.USER: [scanners], Role.ASSISTANT: [scanners]} dict; agentgateway's per-MCP-method Request/Response phase map; OpenAI SDK's first-agent-input / last-agent-output / every-tool-call placement rules.
  - Middleware lifecycle hooks with early-exit jump semantics inside agent loops: before_agent/after_agent/around-model/around-tool, jump_to:'end', tripwire exceptions.
  - Explicit sync-vs-parallel screening semantics as a config choice: OpenAI SDK parallel (latency-optimized, tokens at risk) vs blocking input guardrails; verdict caching to control LLM-judge cost (Claw Patrol).
  - Trace-level sequence matching over multi-step agent behavior rather than single-message classification: Invariant's (call: ToolCall) -> (call2: ToolCall); AlignmentCheck auditing chain-of-thought against the stated goal; death-spiral detection over request patterns.
  - Typed reversible redaction placeholders (<<REDACTED:FIELD_N>>, [REDACTED_{PII_TYPE}], {NAME}) so downstream reasoning proceeds over sanitized content and masks can be audited or restored.

PITFALLS:
  - Almost every deployed system screens user-to-model traffic; inter-agent message screening is nearly vacant — only Invariant (trace policies), LlamaFirewall (per-role scanners, CoT audit), and MCP gateways (tool-hop only) touch it, and none propagates trust/provenance metadata between agent hops.
  - Classifier-based detection is probabilistic and cannot be the enforcement layer: prompt injection is an architectural property of undifferentiated token streams (OWASP LLM #1, +340% YoY), guard models are themselves bypassable, and PISmith-style automated red teaming keeps finding holes — detectors must feed policy signals, with authority in capability restriction.
  - Advisory interposition is a smoke test: HTTPS_PROXY / OPENAI_BASE_URL env-var proxying can be routed around by the agent's own code; enforcement must live at a boundary the agent cannot cross (network namespaces, VPC egress, gateway-side gRPC processors with FailClosed).
  - LLM-judge screening adds cost, latency, and a new injectable surface; systems that use it need verdict caching (Claw Patrol) and cheap dedicated judge models, and still pay ~hundreds of ms to seconds per hop (published frontier: 94.9% F1 at 5.4 s vs 81.7% at 850 ms).
  - Policy-DSL proliferation with zero interoperability: Colang, HCL+CEL, Invariant's rule language, RAIL, CRDs — every vendor's policies are non-portable, which suppresses ecosystem reuse of actual security rules.
  - Guardrail placement defaults leave gaps: OpenAI SDK runs input guardrails only on the first agent and output guardrails only on the last, so intermediate agent-to-agent handoffs in a workflow are unscreened unless explicitly wired.
  - Rails designed for single-turn chat break agent loops: blocking with a canned message mid-plan corrupts multi-step state, and silent mask/rewrite actions change semantics of content that downstream agents then reason over.
  - Fail-open is the implicit default in most middleware (a crashed validator lets traffic through); explicit failureMode declarations are rare outside agentgateway.
  - Category churn and vendor fragility: 'LLM firewall' vs 'agent firewall' vs 'MCP gateway' boundaries are contested marketing; startups pivot (Guardrails AI docs now live under snowglobe.so), so betting a stack on one vendor's policy format is risky.
  - The strongest 2026 defenses (privilege separation by source trust, counterfactual tool-call attribution, sandboxed untrusted context) exist only as papers — no production system yet ships graduated-trust enforcement.

IMPLICATIONS:
  - COPY: gateway-side interposition with an external-processor contract — agentgateway's per-method {Request|Response} phase map plus gRPC CheckRequest/CheckResponse with explicit failureMode is the cleanest deployed shape for screening protocol messages; a layered agent-communication stack should make this a first-class layer, not an app library.
  - COPY: a standardized verdict envelope rather than a boolean — Bedrock's {action: NONE|INTERVENED, outputs (masked/canned), assessments-per-policy with confidence} and LlamaFirewall's ScanResult{decision, reason, score} are convergent; define one wire-level ScanResult type so heterogeneous guards (regex, NER, guard models, LLM judges) plug in interchangeably.
  - COPY: the small closed action vocabulary (allow / block / redact-with-typed-placeholders / rewrite / ask / flag) and Llama Guard's category-coded taxonomy (align with MLCommons S-codes) so verdicts are machine-actionable and comparable across guards.
  - AVOID: inventing another standalone policy DSL; if policies are needed, Invariant's trace-level sequence matching over (Message, ToolCall, ToolOutput) is the most agent-native model — but prefer delegating classification to pluggable external guard services and keeping the stack's own policy surface minimal.
  - FILL THE GAP: no existing system carries trust/provenance labels in the message envelope across agent hops; a new stack should stamp per-message source-trust and taint metadata (the NVIDIA/JHU graduated-trust and AttriGuard attribution papers describe exactly what enforcement needs but lacks transport for) so screening can be trust-conditional and tool-call authorization can attribute intent.
  - FILL THE GAP: screen every hop, not first-input/last-output — per-role, per-edge scanner registration (LlamaFirewall's dict shape generalized to arbitrary agent pairs) should be the default placement model for inter-agent traffic.
  - COPY: explicit sync-blocking vs parallel screening semantics per rail, streaming-aware output screening, and content-keyed verdict caching — these are the three latency levers deployed systems converged on; budget ~100 ms for classifier guards and treat LLM-judge rails as 'ask'-tier only.
  - AVOID: making detection load-bearing — architect so guards emit signals into an authorization layer enforcing least-privilege capabilities, with human/LLM 'ask' escalation for high-blast-radius actions; the enforcement boundary must be one the agent process cannot reconfigure (fail-closed gateway, not env-var proxy).
  - COPY: progressive rollout modes (audit/flag-only before enforce) and full-output debug scope (Bedrock outputScope: FULL) — operationally these are what let teams actually turn screening on in production.

AREA: Identity and message attribution for autonomous software

SUMMARY: Agent identity in mid-2026 is a two-speed world: workload identity (SPIFFE/SPIRE, now wrapped by IETF WIMSE) is production-proven and is what serious efforts compose, while agent-specific standards are a crowd of 10+ Internet-Drafts, W3C community groups, and DIF donations with zero RFCs and security-considerations sections literally marked TODO. The emerging industry consensus, exemplified by the AIMS draft (AWS/Zscaler/Ping/Defakto), is to map existing standards — SPIFFE URIs and SVIDs for identity, OAuth 2.x token exchange with sub/act claims for delegation, RFC 9421 HTTP Message Signatures for per-message attribution — onto a layered stack rather than invent new protocols. DID/VC approaches for agents remain prototypes with resolution-latency and LLM-in-the-loop security problems, though delegation-chain designs (AIP, MCP-I) are conceptually informative. For message signing at internet scale, Cloudflare's Web Bot Auth (Ed25519 + Signature-Agent header + JWKS well-known directory, now an IETF httpbis draft backed by Amazon/Akamai/OpenAI) is the most practically adoptable pattern, and key transparency has real production infrastructure (WhatsApp/Messenger AKD, facebook/akd library, Cloudflare auditor, IETF KEYTRANS WG) if the threat model warrants it.

INTERFACE_PATTERNS:
  - Hierarchical URI identity namespace (spiffe://trust-domain/path) with exactly one identifier per principal, issued as short-lived, auto-rotated credentials — never static API keys.
  - Local, unauthenticated credential-delivery endpoint (SPIFFE Workload API pattern): the platform attests the workload out-of-band, then hands it identity + keys + trust bundles, so the agent process never holds long-lived bootstrap secrets.
  - Dual credential formats per identity — X.509 for transport mTLS, JWT for application layer — each verified against a distributed trust bundle; X.509/PoP preferred because bare JWTs replay.
  - Attestation-gated issuance: credentials minted only after verifying process/platform properties (image digest, service account, TEE evidence) against registered selectors.
  - Proof-of-possession binding tokens to message context: DPoP proofs, WIMSE Proof Tokens (`aud`/`exp`/`jti`/`wth` over a Workload Identity Token, `Workload-Proof-Token` header), and RFC 9421 signatures over method + target + content-digest — sign the message, not just the channel.
  - Delegation as claim chains inside tokens: RFC 8693 token exchange producing `sub` (human principal) + `act` (acting agent) claims, with down-scoped transaction tokens per hop; DID/VC variants encode the same chain as nested signed credentials.
  - Discovery via well-known HTTPS documents: `Signature-Agent` header pointing to a JWKS directory (Web Bot Auth) and `/.well-known/agent.json` cards (A2A) — DNS + TLS as the trust root instead of a ledger.
  - Transparency-log key distribution: append-only Merkle-tree directory with epochs, VRF-privatized lookups, self-monitoring, and an independent third-party auditor for the malicious-directory threat model.
  - Real-time revocation as push events (Shared Signals Framework / CAEP) layered on top of short token expiry, plus mandated audit tuples (agent id, delegated subject, resource, action, decision, correlation ID).
  - Layered composition over invention: AIMS's 8-layer stack (identifier -> credentials -> attestation -> provisioning -> authn -> authz -> monitoring -> policy) reuses existing standards at every layer and leaves policy format deliberately out of scope.

PITFALLS:
  - Agent-specific identity standards are premature: 10+ competing Internet-Drafts, none at RFC; the flagship AIMS draft's Security Considerations section is literally 'TODO Security' — do not build on any single agent-identity draft as a stable dependency.
  - Credentials attest identity, not intent: a prompt-injected ('puppeteered') agent presents perfectly valid credentials; TEEs attest code integrity and ZKPs prove statements, but nothing verifies the agent is executing its principal's intent (the 'semantic intent gap').
  - DID/VC hot-path costs: blockchain-resolved DID methods add latency and availability failure modes incompatible with high-throughput agent-to-agent delegation; the published agent DID/VC prototype degraded specifically when the LLM itself was in charge of security procedures.
  - OAuth's human assumptions leak through: synchronous consent screens and browser redirects don't exist for autonomous agents, CIBA doesn't scale to agent throughput, and no production protocol exists for multi-hop cross-organizational delegation with enforced scope attenuation or cross-org audit correlation.
  - Coarse authorization at the tool boundary (MCP's documented gap): one authentication implicitly grants every exposed tool, creating confused-deputy risk, privilege concentration, and no mapping from OAuth scopes to individual capabilities.
  - Self-declared identity documents without third-party attestation (A2A Agent Cards) are spoofable by construction; signing the card only proves possession of the self-chosen key.
  - Channel-only authentication breaks at intermediaries: mTLS identity is destroyed by TLS-terminating proxies/gateways/meshes, which is exactly why the drafts add application-layer message signatures.
  - A key directory without transparency machinery provides no protection against its own operator; but full key transparency is operationally heavy (epoch pipelines, independent auditor, out-of-band consistency channel) — deploying half of it (log without auditor/monitoring) yields false assurance.
  - Governance theater: surveyed organizations report 82% governance confidence against 47% actual monitoring coverage; identity systems without mandated audit tuples and revocation eventing become paperwork.

IMPLICATIONS:
  - Copy SPIFFE's shape for the identity layer: hierarchical URI per agent, short-lived attested credentials delivered by a local workload API, trust bundles per domain. It is the only production-proven layer in this space, and the industry drafts (AIMS, WIMSE agent drafts) all compose it rather than replace it — a research stack that does likewise inherits interop for free.
  - Make per-message signing, not per-connection auth, the attribution primitive: an RFC 9421 profile (sign method + target + content-digest + identity token, Ed25519, keyid = JWK thumbprint) survives proxies and gives non-repudiable message attribution; Web Bot Auth's three-header shape (Signature-Agent / Signature-Input / Signature) is a directly copyable minimal design.
  - Model user->agent delegation as claim chains with explicit attenuation at each hop (RFC 8693 exchange, sub = human principal, act = agent, down-scoped transaction tokens per hop) rather than in DID documents; keep DID/VC as an optional edge encoding for cross-org portability, out of the hot path, because DID resolution costs and LLM-managed-wallet failure modes are documented.
  - For a research testbed, key distribution via HTTPS well-known JWKS directories gets ~90% of the value at ~5% of the cost; if the threat model includes a malicious directory, facebook/akd is an off-the-shelf transparency log and IETF KEYTRANS provides the interface vocabulary (search / update / monitor / audit, epoch-versioned Merkle roots, independent auditor) worth mirroring so the testbed can upgrade later without an interface break.
  - Design for the compromised-but-credentialed agent: since no layer verifies intent, the stack must make attribution and containment cheap — mandatory audit tuples (agent id, delegated subject, action, correlation ID) on every message, short expiries plus push revocation (CAEP-style events), and per-capability rather than per-server authorization to avoid MCP's all-tools-at-once gap.
  - Avoid making the LLM the security enforcement point (signing, credential selection, and policy checks belong in a deterministic runtime beneath the model), avoid self-asserted identity documents without attestation, and avoid binding to any specific agent-identity Internet-Draft — target the stable substrates (SPIFFE, OAuth RFCs, RFC 9421, RFC 8693) and treat the agent-specific layer as a thin, replaceable profile.

AREA: Tamper-evident records, accountability, revocation, and reputation in distributed systems

SUMMARY: Tamper-evident logging is a solved, production-hardened problem with reusable tooling: the Crosby-Wallach history-tree design (USENIX Sec '09) became Certificate Transparency (RFC 6962/9162), then generalized into Google Trillian and its successor Tessera, a Go library for tile-based transparency logs that backs Rekor v2 (Sigstore), with real adoption via npm provenance (GA, 16k+ packages) and PyPI attestations (GA Nov 2024, 20k+ attestations). Accountability-as-blame-assignment was worked out by PeerReview (SOSP '07): signed hash-chained per-node logs plus witness auditing yields non-repudiable evidence of Byzantine faults and provable defense against false accusation, but it requires deterministic replay and never saw production adoption. Revocation has converged on aggregate-and-push: Mozilla CRLite compresses all Web-PKI revocations (derived from CT data) into Bloom-filter cascades shipped to Firefox (deployed to all desktop users in 2025), displacing per-connection online checks. Reputation/trust for multi-agent systems remains largely academic (FIRE, ReGreT, EigenTrust, Beta Reputation; Pinyol & Sabater-Mir survey), though a 2025 comparative study of agentic-web protocols (arXiv 2511.03434, covering A2A, AP2, ERC-8004) proposes composing six trust signal classes (brief/claim/proof/stake/reputation/constraint) in risk-calibrated tiers. The persistent gap everywhere is the verification side: CT-style logs succeed at deterrence, but client-side auditing (SCT auditing, goss

INTERFACE_PATTERNS:
  - Append-only Merkle log with a signed head as the universal commitment: client verification state collapses to one (tree size N, root hash T) pair; everything else is inclusion proofs (record in tree N) and consistency proofs (tree N is a prefix of tree N') — identical shape in CT (get-sth/get-proof-by-hash), Go sumdb (Latest/RecordProof/TreeProof), and Rekor.
  - Tile-based static reads over proof RPCs: serve immutable Tile(level, index) blobs from dumb storage/CDN and let clients assemble their own proofs — the design every current system (tlog-tiles, Tessera, Rekor v2, CT static API) converged on because per-proof endpoints don't cache and leak queries.
  - Role separation Log / Monitor / Auditor / Witness: the log commits, monitors watch content for policy violations, auditors check the log's own promises, witnesses cosign checkpoints to prevent split-view — each role has an independent interface and can be run by different parties.
  - Signed inclusion promise (SCT pattern): issue a signed 'will include within MMD' receipt synchronously, do Merkle integration asynchronously — decouples the hot path from log sequencing; the promise itself becomes the artifact carried in-band.
  - PeerReview authenticator pattern for non-repudiation: every message carries a signature over the sender's current hash-chain position, so receiving any message yields transferable evidence of the sender's log state; audits then replay log segments against a reference to assign blame, and evidence is a portable proof usable by third parties.
  - Minimal, closed entry-type vocabulary: Rekor v2 cut eleven entry types to two (hashedrekord for artifact signatures, dsse for arbitrary attestations) — the generic signed-envelope type (DSSE) absorbs extensibility so the log schema stays frozen.
  - Separation of time, search, and storage from the log: timestamps from a dedicated RFC 3161 TSA, lookup indexes and payload blobs in separate (independently verifiable) services; the log holds only hashes/signatures.
  - Revocation as compiled artifact, not query: derive the revocation set from transparency data, compress (Bloom-filter cascade), and push on a fixed cadence with local lookup — CRLite's replacement for per-use online status checks.
  - Trust as composition of typed signals with risk tiering: brief/claim/proof/stake/reputation/constraint as distinct interface layers (AgentCard-style self-claims at the bottom, verifiable-credential mandates, then validation registries with re-execution/attestation), escalating with action consequence (T0-T3).
  - Reputation values carried with confidence/reliability metadata and decay: FIRE/ReGreT/Beta all pair the trust score with a reliability measure derived from evidence volume and recency rather than exposing a bare scalar.

PITFALLS:
  - The auditing half of CT never shipped: browsers require SCTs but do no SCT auditing (Chrome mandates one Google-operated log instead), gossip protocols were never deployed, and per-connection inclusion-proof fetching failed on both load and privacy (the proof request reveals which site you visited). A log that no independent party audits degrades to a trusted database with extra hashes.
  - Monitoring centralization: in practice a handful of well-resourced monitors (mostly Google and commercial services) watch CT logs; the 'anyone can run a monitor' story is true but almost no one does — plan for funded, first-party monitors, not emergent community ones.
  - Trillian v1's microservice + personality architecture was too expensive and complex to operate for small logs; the field corrected to an embeddable library (Tessera) with commodity storage. Don't design the log as a standalone service tier.
  - Entry-type sprawl: Rekor v1 accumulated eleven entry types that all had to be maintained and verified forever; v2's painful cut to two shows extensibility belongs in a generic signed envelope (DSSE), not in the log schema.
  - Mutable/auxiliary state in the log: Rekor v1 put a search index, attestation storage, and log-signed timestamps inside the log service and had to excise all three — a trustworthy timestamp from the log being audited is circular, and indexes can't be tamper-evident the same way.
  - PeerReview's determinism requirement is its adoption killer: replay-based blame assignment needs a deterministic reference implementation and full message logging (witness overhead grows with witness-set size); no production system accepted that cost, and it is a fundamentally poor fit for nondeterministic (LLM) agents.
  - Blame vs. detection conflation: accountability needs three separable properties (non-repudiable actions, tamper-evident record, auditability) — systems that log without signing get tamper-evidence but no blame; systems that sign without third-party-verifiable evidence can't survive false-accusation disputes.
  - Academic reputation models (FIRE, ReGreT, EigenTrust, Beta) validated only in simulation; known failure modes are structural: Sybil creation, whitewashing (re-entry with fresh identity), colluding rating rings (defeats EigenTrust), rating inflation, cold-start, and context collapse (one scalar score across unlike tasks). EigenTrust additionally requires an a-priori pre-trusted peer set — a hidden centralization.
  - Reputation without evidence anchoring: feedback that isn't tied to non-repudiable interaction records is free to fabricate; the agentic-protocol survey's core criticism of pure-reputation designs (and of unsigned AgentCard-style claims) is exactly this — and it adds LLM-specific fragilities (prompt injection, sycophancy) that make self-claims and history even weaker signals.
  - Blockchain-anchored rebuilds of transparency logs (revocation-on-chain, ledger-per-audit-log papers) repeatedly rediscover what a signed checkpoint plus independent witnesses provides at a fraction of the cost; consensus is unnecessary when there is a single log operator whose equivocation you only need to detect, not prevent.
  - Publish-side adoption is not verify-side adoption: npm/PyPI attest millions of artifacts, but few consumers verify at install time; measuring success by log write volume repeats CT's asymmetry.

IMPLICATIONS:
  - Do not write a Merkle log: build the record layer on Trillian Tessera (Go library, POSIX/MySQL/GCP/AWS backends) or at minimum adopt the tlog-tiles wire format (checkpoint note + Tile(L,K) static reads), so existing verifiers, witnesses, and tooling work unmodified.
  - Copy the tlog client contract exactly: agents/clients persist only (size, root hash) and verify consistency proofs on every head update — this is the cheapest possible tamper-evidence and is battle-tested in Go sumdb and CT.
  - Copy PeerReview's message-level primitives without its replay engine: every inter-agent message carries a signature binding it to the sender's hash-chain position (authenticator), making evidence non-repudiable and transferable; but replace deterministic-replay blame with commitment + spot-check validation (log hashes of inputs/outputs, audit via re-execution, attestation, or judge-model checks per the ERC-8004 Validation Registry / T2-tier pattern), since LLM agents are nondeterministic.
  - Design the auditor/witness story before the log ships, or it will never exist (CT's lesson): fund first-party monitors, require witness-cosigned checkpoints for split-view protection, and never make verification an on-path per-message network call — commit synchronously (SCT-style signed promise), audit asynchronously off-path.
  - Keep the log schema closed and tiny: two entry types (an artifact-hash record and a DSSE-style attestation envelope) absorb all extensibility; put timestamps in a separate timestamping authority and search/payload storage in separate services the log only commits to by hash.
  - Build revocation as a compiled push artifact, CRLite-style: derive the revoked-credential/agent set from the transparency log itself, compress (Bloom-filter cascade), distribute on a cadence, check locally — never an online status check on the message path.
  - Treat reputation as a derived view over the evidence layer, never a primary store: scores computed from non-repudiable logged interactions (so feedback is accountable and disputable), carried with confidence + recency decay (Beta/FIRE pattern), scoped per capability/context rather than one global scalar, and Sybil-bounded by identity cost (registration in an identity registry, optional stake).
  - Adopt the six-signal composition and risk tiering from the agentic-protocol literature as the trust API shape: self-claims (AgentCard-like) for discovery only, verifiable-credential mandates for delegated authority, cryptographic proof + collateral + human gating escalating with action consequence — no single mechanism gates a consequential action.
  - Avoid consensus/blockchain machinery for the core log: a single-operator signed log with independent witnesses gives equivocation detection at commodity cost; reserve on-chain registries (ERC-8004 style) for the narrow case of cross-organization identity/stake where no operator is mutually acceptable.
  - Instrument verify-side adoption from day one (what fraction of consumed messages/credentials are actually proof-checked), because the recurring failure across CT, npm, and PyPI is write-side success masking absent verification.
