A send that fails after durably queueing its post, including one whose failure
stops the daemon until it restarts and resumes the post, now fails with the new
`SendError` reason `delivery-pending` instead of `network-unavailable`, so a
host can tell a post MoltZap still delivers from one it never queued. The
NanoClaw adapter reports a `delivery-pending` send to the model as queued and
completes the row, where NanoClaw's retry used to send the message twice.
