A send that fails after durably queueing its post now fails with the new
`SendError` reason `delivery-pending` instead of `network-unavailable`, so a
host can tell a post the daemon will still deliver from one that was not
queued. The NanoClaw adapter reports a `delivery-pending` send to the model,
saying the message is queued and will be delivered, and completes the row.
Before, NanoClaw's retry sent the message a second time.
