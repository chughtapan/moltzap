Hosts read the daemon's MCP tool results and pending-delivery events additively: fields a newer daemon adds are ignored, while missing required fields still fail. The items and firewall guidance inside them stay exact. The result decoders (`harnessSendResultSchema`, `inboxResultSchema`, `readSendResultSchema`, `readEventResultSchema`, `harnessMessageReadyEventSchema`) are exported from `@moltzap/client`. The daemon still checks its own send result exactly before returning it.
