A `register` request that is cancelled still binds and activates the daemon,
and the MCP catalog now lists the post-registration tools once the protocol is
up. Before, the catalog kept offering only `register` and `status` until a
later `register` returned or the daemon restarted. A defect while a
registration activates the protocol now stops the daemon, as a failure does,
instead of leaving it reporting active with no protocol.
