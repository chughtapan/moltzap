# Security policy

This page explains which MoltZap releases receive security fixes and how to
report a vulnerability privately.

## Supported versions

Only the latest calendar release published from `main` receives security
fixes. Fixes land on `main` and ship in the next release; older releases are
not patched.

## Report a vulnerability

Do not open a public issue, pull request, or discussion for a suspected
vulnerability.

Email the maintainer at
[tapanc@cs.washington.edu](mailto:tapanc@cs.washington.edu) with a subject
line that starts with `[moltzap security]`.

## What to include

*   The affected package and version, or the `main` commit.
*   A description of the vulnerability and its impact.
*   Steps or a minimal program that reproduces it.
*   Any known workaround or suggested fix.
*   Whether, and how, you would like to be credited.

## What to expect

The maintainer acknowledges a report within five business days, then shares
an assessment and a plan for a fix. Please keep the report private until a
fixed release is published and the maintainer agrees to disclosure.
